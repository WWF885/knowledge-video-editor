> 组件是"表达工具"，不是"装饰清单"。选错组件 = 用错语言。

## 2. 选组件的判断路径

```
这句话是什么类型？
├─ 定义/概念 → V03 关键词 → 需要展开时 V05 思维导图
├─ 步骤/方法 → V04 流程步骤图
├─ 对比/纠偏 → V06 新旧对比
├─ 数据/趋势 → V07 数据统计图（单个数 → V18 数字滚动）
├─ 时间/经历 → V09 时间轴
├─ 因果/机制 → V19 因果链
├─ 罗列/清单 → V13 知识卡片
├─ 引用/政策 → V14 证据引用
├─ 地域 → V11 地图
├─ 操作 → V10 录屏
├─ 情绪/立场 → V01 真人
└─ 总结 → V20 总结图
```

**一句话只用一个主组件。** 想用两个，说明这句话该拆成两个镜头。

## 4. 组件扩展规则（允许自建）

当内容没有对应组件时，**必须创造，不许放弃可视化**。允许的形式：

- 二维示意图 / 剖面图
- 空间关系图 / 象限图
- 模拟实验动画
- 逻辑谜题分解动画
- 流程沙盘

新组件要求：

1. 放进 `templates/remotion/src/components/`，命名 `Cxx_Name.tsx`（C 表示 Custom）。
2. 遵守同一主题 token（颜色从 theme 取，不许硬编码）。
3. 遵守安全区与字幕避让。
4. 在 README 的组件表登记一行。

## 5. 使用纪律

- **一屏 ≤ 5 个信息元素**。
- **同级元素样式统一**（同字号、同圆角、同间距）。
- **动效只强调重点**：一屏最多 2 处强调动画。
- **数据必须有单位与出处**（V07/V18/V14 必带 `source`）。
- **不用组件替代观点**：观众记不住 20 张图，只记得 1 个结论。

## 6. 常见错误

| 错误 | 后果 | 修法 |
|---|---|---|
| 全程 V13 卡片 | 变成动态 PPT | 每 2–3 个卡片镜头插一个真人或图表 |
| 数据图无单位/来源 | 可信度归零 | 补 `unit` / `source` |
| 流程图节点超过 6 个 | 看不清 | 拆成两屏，或合并层级 |
| 对比图两侧字数不等 | 视觉失衡 | 压缩到同字数 |
| 动画全屏乱飞 | 廉价 | 每屏 ≤ 2 处动效 |
| 头像圆内只剩一张脸 | 头被"砍”，观众出眼 | 按 §7.2 三参数重调取景并渲静帧验收 |

## 7. V21 真人圆形头像（强制组件）

> 规则来源：观众要"看得见人"。知识画面再漂亮，全片没有真人也不成立。

### 7.1 何时出现
- **每一个画面都要有真人**：`presenter` / `presenter_pip` 镜头本身即真人；除此之外的**所有**镜头（含封面、关键词、流程、对比、卡片、数字、总结、引用）都必须叠加 V21。
- 封面镜头也要有，但直径略小（竖屏 176 / 横屏 216），避免抢标题。

### 7.2 取景三参数（V1.0.2 重做）

取景不是"截一块正方形"，而是"把人装进圆里"。三个参数各管一件事：

| 参数 | 管什么 | 怎么定 |
|---|---|---|
| `focus_x` / `focus_y` | 源片里**人脸中心**的坐标（0–1） | 打开源片量一下：鼻子所在位置 |
| `zoom` | 取景倍数 = 内层画面宽度 / 圆直径 | **1.0 = 标准三件套**（头发+全脸+双肩）；人脸偏小才加到 1.2–1.5 |
| `anchor_y` | 人脸中心落在圆内的纵向位置 | 近景 0.42；宽机位 0.28（给肩颈与衣领留空间） |

必露区域（缺一项即不合格）：

| 必须 | 禁止 |
|---|---|
| 头顶头发，上方留 6–10% 余量 | 发际线被裁、只剩额头 |
| 完整五官与下巴，下巴在圆心下方 | 下巴被圆边切掉 |
| 下巴以下至少 25% 画幅的肩颈与衣领 | 只剩一张脸、看不到肩膀 |

尺寸与位置：

| 参数 | 竖屏 9:16 | 横屏 16:9 |
|---|---|---|
| 直径 | 192px | 240px |
| 右边距 / 顶距 | 48 / 316（导航条之下） | 52 / 152 |
| 内层画面 | 宽 `zoom × 直径`，高按**源片真实宽高比**推算 | 同 |
| 描边与投影 | 3px 白色描边（浅色主题 0.94 / 深色 0.26）+ 柔和投影 | 同 |
| 入场 | 0.4s 淡入 + 0.92→1 轻微放大 | 同 |

> 必须知道源片真实宽高比（`render_video.py` 会自动探针写入 `presenterAspect`），写死 9:16 会把横屏素材裁坏。

### 7.3 位置与避让（绝不压字）
- 固定**右上角**；竖屏必须落在导航条（约 y 230–300）**下方**。
- 内容区让位：竖屏 `padTop ≥ 528`（标题从 y 528 起）；横屏 `paddingRight = padX + 344`。
- 头像与字幕、卡片、图表永不重叠；出现重叠即为不合格，必须调布局而不是缩小头像。
- 验收流程：改参数 → 渲一帧静帧 → 看头发/全脸/双肩 → 通过才开渲全片。

## 8. 顶部动态导航条（V1.0.2 新样式）

| 项 | 竖屏 9:16 | 横屏 16:9 |
|---|---|---|
| 位置 | 距顶 230，左右 40 | 距顶 20，左右 96 |
| 高度 | 76（≤ 画面 8%） | 84 |
| 形态 | 胶囊（圆角 = 高度/2）+ 毛玻璃 + 1px 细描边 + 柔和投影 | 同 |
| 当前章 | 一块随切换**滑动的高亮块**（0.4s 弹簧），字号加粗、主文字色 | 同 |
| 已完成章 | 强调色圆点 + 0.88 透明度 | 同 |
| 未开始章 | 空心圆点 + 0.52 透明度 | 同 |
| 进度 | 容器底部 2px 强调色细线，宽度 = 已完成章节比例 | 同 |
| 禁止 | 旧版的"文字 + ✓ + 短横线"堆砌、每章间距不均、进度条与文字争位 | 同 |
