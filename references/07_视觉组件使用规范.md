# 07 · 视觉组件使用规范

> 组件是"表达工具"，不是"装饰清单"。选错组件 = 用错语言。

## 1. 组件总表（V01–V21）

## 2. 选组件的判断路径

```
这句话是什么类型？
├─ 定义/概念 → V03 关键词 → 需要展开时 V05 思维导图
├─ 步骤/方法 → V04 流程步骤图
├─ 对比/纠偏 → V06 新旧对比
├─ 数据/趋势 → V07 数据统计图（单个数 → V18 数字滚动）
├─ 时间/经历 → V09 时间轴
├─ 因果/机制 → V19 因果链
├─ 罗列/清单 → V13 知识卡片
├─ 引用/政策 → V14 证据引用
├─ 地域 → V11 地图
├─ 操作 → V10 录屏
├─ 情绪/立场 → V01 真人
└─ 总结 → V20 总结图
```

**一句话只用一个主组件。** 想用两个，说明这句话该拆成两个镜头。

## 3. 每个组件的必要参数

组件必须能被程序渲染，所以每个组件在 `storyboard.json` 里都要有可执行参数：

| 组件 | 必需字段 |
|---|---|
| V03 | `keywords[]`, `emphasis_index` |
| V04 | `nodes[]`, `direction`, `step_interval` |
| V05 | `root`, `branches[{text, children[]}]` |
| V06 | `left{title,items[]}`, `right{title,items[]}` |
| V07 | `series[{label,value}]`, `chart`(bar/line), `unit` |
| V08 | `levels[[{label}], ...]` |
| V09 | `events[{time,title,desc}]` |
| V10 | `clip_path`, `zoom_regions[{t,x,y,w,h,scale}]` |
| V11 | `geo`, `routes[{from,to}]`, `focus` |
| V13 | `cards[{title,body}]` |
| V14 | `source`, `quote`, `highlight_range` |
| V18 | `from`, `to`, `unit`, `duration` |
| V19 | `chain[{cause, effect}]` |
| V20 | `points[]`, `conclusion` |
| V21 | 无需逐镜字段：`presenter.badge{focus_x,focus_y,zoom}` 全局统一，单镜可用 `avatar:false` 显式关闭 |

## 4. 组件扩展规则（允许自建）

当内容没有对应组件时，**必须创造，不许放弃可视化**。允许的形式：

- 二维示意图 / 剖面图
- 空间关系图 / 象限图
- 模拟实验动画
- 逻辑谜题分解动画
- 流程沙盘

新组件要求：

1. 放进 `templates/remotion/src/components/`，命名 `Cxx_Name.tsx`（C 表示 Custom）。
2. 遵守同一主题 token（颜色从 theme 取，不许硬编码）。
3. 遵守安全区与字幕避让。
4. 在 README 的组件表登记一行。

## 5. 使用纪律

- **一屏 ≤ 5 个信息元素**。
- **同级元素样式统一**（同字号、同圆角、同间距）。
- **动效只强调重点**：一屏最多 2 处强调动画。
- **数据必须有单位与出处**（V07/V18/V14 必带 `source`）。
- **不用组件替代观点**：观众记不住 20 张图，只记得 1 个结论。

## 6. 常见错误

| 错误 | 后果 | 修法 |
|---|---|---|
| 全程 V13 卡片 | 变成动态 PPT | 每 2–3 个卡片镜头插一个真人或图表 |
| 数据图无单位/来源 | 可信度归零 | 补 `unit` / `source` |
| 流程图节点超过 6 个 | 看不清 | 拆成两屏，或合并层级 |
| 对比图两侧字数不等 | 视觉失衡 | 压缩到同字数 |
| 动画全屏乱飞 | 廉价 | 每屏 ≤ 2 处动效 |

## 7. V21 真人圆形头像（强制组件）

> 规则来源：观众要"看得见人"。知识画面再漂亮，全片没有真人也不成立。

### 7.1 何时出现
- **每一个画面都要有真人**：`presenter` / `presenter_pip` 镜头本身即真人；除此之外的**所有**镜头（含封面、关键词、流程、对比、卡片、数字、总结、引用）都必须叠加 V21。
- 封面镜头也要有，但直径略小（竖屏 176 / 横屏 216），避免抢标题。

### 7.2 取景（圆内必须装下什么）
| 必须 | 禁止 |
|---|---|
| 头发顶部、完整五官、下巴、上肩与衣领 | 裁掉额头、裁掉下巴、只有眼睛和鼻子 |
| 人脸略偏中上，四周留 8–12% 余量 | 人脸贴边、脸被圆框切到 |

实现参数（`config/default.json → presenter.badge`）：

| 参数 | 竖屏 9:16 | 横屏 16:9 |
|---|---|---|
| 直径 | 192px | 240px |
| 右边距 / 顶距 | 48 / 312（导航条之下） | 52 / 152 |
| 内层画面宽 | 1.02 × 直径 | 同 |
| 取样中心 | `focus_y=0.34`、`focus_x=0.62`（按人物站位实测） | 同 |
| 取景放大 | `zoom=1.0`（近景口播）；全身/宽机位调到 1.2–1.8 | 同 |

> 人物站位不同时必须实测 `focus_x` / `focus_y`：以"眉毛在圆心上 1/4、下巴在圆心下 1/4"为准。

### 7.3 位置与避让（绝不压字）
- 固定**右上角**；竖屏必须落在导航条（约 y 230–300）**下方**。
- 内容区让位：竖屏 `padTop ≥ 528`（标题从 y 528 起）；横屏 `paddingRight = padX + 344`。
- 头像与字幕、卡片、图表永不重叠；出现重叠即为不合格，必须调布局而不是缩小头像。
- 描边 3px 白色 + 柔和投影，浅色主题用 0.92 白描边，深色主题用 0.22 白描边。
